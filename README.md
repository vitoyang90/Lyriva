# Lyriva

App 與小工具對外名稱已更新為 Lyriva。為沿用既有安裝、登入與 Spotify 回呼設定，Xcode 專案／target、Bundle ID、App Group、Keychain 識別與 URL scheme 保留原值。圖示來源與生成提示見 [設計紀錄](design/lyriva-icon-prompt.md)。

iOS 18.4+ 的 Spotify 跟唱 App。手機直接取得歌曲狀態與歌詞，在裝置上產生羅馬字，依播放進度反白與捲動。日常使用不需要電腦、Docker 或自架後端。

## 歌詞優先主畫面

- 歌詞標題旁的「展開歌詞」可切換全畫面閱讀，底部保留置中的播放控制；再按「收合歌詞」回到原版面。展開、收合與旋轉共用歌詞及閱讀狀態，不重新載入歌曲。展開／收合使用 0.25 秒動畫，「歌詞選項」與縮放按鈕固定成一組，共用位置動畫，縮放箭頭與固定 44 點圓形底色同步移動；箭頭切換另以 0.15 秒只動畫透明度。按下時只有箭頭變淡，底色不變；啟用「減少動態效果」時直接切換版面與箭頭。

- 直向將播放器置於頂部，上半部固定排列、不使用 ScrollView，只有歌詞區獨立捲動並填滿剩餘高度。一般尺寸保留大封面與 64 點播放鍵；小螢幕及橫向使用較緊湊的封面與 48 點播放鍵，切換至 Spotify／更新權限集中在「更多播放操作」選單，模式切換直接顯示。「回到目前歌詞」會平滑捲回播放中的句子；系統啟用「減少動態效果」時直接定位。
- 點播放器的歌名／封面，在原卡片內以共用的 0.32 秒平滑動畫放大封面並展開完整歌名、一般／跟唱模式與播放裝置資訊，不再升起另一個頁面；再點同一處收合。封面預留固定空間，縮放時不擠壓歌名；卡片與歌詞區由同一個版面動畫配置，上下箭頭旋轉切換。開啟「減少動態效果」時直接切換。進度條與播放控制共用同一份檢視，縮放不重新載入歌曲、改變播放進度或重啟翻譯；手動閱讀狀態保留，播放中繼續跟隨目前歌詞。收藏、上一首、播放／暫停、下一首與更新依序排列，兩側操作各保留 44 點區域，播放鍵維持置中。
- 橫向依實際可用寬高採左右欄，左欄寬度隨空間調整，歌詞使用右欄剩餘寬度與完整高度；較窄視窗回到上下排列。

## 介面

採用墨綠深色背景、萊姆綠重點色、自訂播放器卡片與歌詞排版。播放器顯示 Spotify 回傳的專輯封面，缺少封面或載入失敗時顯示唱片圖案。主畫面僅提供 Spotify 播放控制及同步原文／羅馬字／繁體中文，首次使用依序顯示「用途介紹 → 連接 Spotify → 啟用歌詞（可稍後）→ 開始使用」；完成後直接進入播放器，授權過期或登出不重播介紹。升級時已有播放登入的使用者直接進播放器。設定使用獨立頁面與原生返回導覽，保留帳號管理入口。沒有手動貼上或範例歌詞入口。

歌詞區右上角的「歌詞選項」開啟底部面板，集中設定原文／羅馬字／中文翻譯、歌詞語言、字級、自動捲動及重新載入歌詞。跟唱模式另外提供逐詞／逐字音節反白選擇，並顯示推估時間的限制；播放操作、點歌詞跳播和每行讀音提示維持直接操作。橫向使用可捲動的完整面板，直向可向上展開。

手動捲動歌詞後會暫停自動跟隨，放開手指後仍可停留閱讀；換句、翻譯更新或調整顯示不會拉回播放位置。點「回到目前歌詞」立即恢復跟隨，換歌時也會恢復；若已在歌詞選項關閉自動捲動，則維持關閉。

設定提供「閱讀時保持螢幕亮著」，預設關閉並保存選擇。啟用後，前景顯示歌詞時暫停系統自動鎖定，暫停播放也適用；沒有歌詞、進入其他頁面或面板、離開 App 後恢復自動鎖定，回到歌詞時重新套用。

## 收藏歌曲與播放模式

點收藏歌曲後，可選擇「一般播放」或「跟唱模式」，確認後才播放；取消選擇會留在收藏清單。兩種模式共用指定歌曲播放，切歌使用已保存的 Web API 授權；過期憑證自動更新並重送一次，不因收藏切歌、空播放回應或找不到裝置而啟動 SDK 驗證。

- 沿用 Spotify 目前使用中的裝置。選歌前讀取裝置清單，將播放指令明確送至該裝置；電腦在播就控制電腦，手機在播就控制手機，不自動轉移到其他裝置。播放器顯示裝置名稱。
- 讀取裝置需要 `user-read-playback-state`。舊授權提供「更新播放裝置權限」的一次性入口；更新後保存權限並隨 Token 自動續期。尚未更新時仍可使用原本的目前裝置控制，不強制彈出驗證。
- 若沒有使用中的裝置，或該裝置禁止遠端控制，顯示具體提示，不自動啟動另一台裝置。播放指令成功仍須等待實際歌曲；連續兩次空播放回應時，只透過保存的連線重查目前裝置並重送選曲一次，不重複授權或無限重試。
- 連續選歌只保留最新選擇。從收藏選定的跟唱模式只套用到該首歌；也可使用播放器的「一般／跟唱」切換按鈕，讓模式隨 Spotify 佇列延續。兩種模式都能點擊有時間標記的歌詞跳播。
- 跟唱模式預設逐字／音節反白，也可在歌詞選項切換逐詞；原文與羅馬字依播放位置更新，暫停時停住，跳播時重新定位。現有歌詞只有整句起始時間，反白依音節權重推估，每句上限 8 秒；下一句或歌曲結尾較早時，以較早者為準。到達上限後清除逐字反白，保留整句位置並等待下一句，最後一句也不會延伸到整段尾奏。畫面明確標示「推估」；這不是人聲偵測，較長的拖音可能提前停止反白，也無法辨識句內停唱。沒有時間標記的歌詞只供閱讀。精準逐字同步仍需可靠的逐字起訖時間。

## 接續 Spotify 推薦播放

播放器提供左右並排的「一般／跟唱」切換按鈕，左側為一般、右側為跟唱，點選後立即套用並顯示選中狀態。切換只改變歌詞顯示模式，保留歌曲、進度與暫停狀態，不發送播放或重新同步指令。Spotify 的推薦歌單與佇列照常播放，不匯入歌單或要求新增歌單權限。

- 上一首、下一首使用 Spotify 的佇列；隨機播放在 Spotify 設定。
- 跟唱模式在手動切歌、Spotify 自動換歌、背景返回與暫時無播放資料時保留；新歌曲沿用既有歌詞載入流程。一般播放也會延續到下一首。
- 模式只保留於這次 App 使用期間，登出或重新啟動後回到一般播放。選收藏歌曲時改用該次收藏選歌的模式。
- 介面測試以兩首模擬歌曲驗證左右模式切換、選中狀態、上下首、歌詞更新及進度／暫停狀態保留；真實 Spotify 帳號與推薦歌單仍需實機驗證。

## 手機使用流程

1. 首次啟動點「開始設定」，再點「連接 Spotify」，登入自己的 Spotify 帳號並同意授權。App 已內建 Client ID，使用者不需進入 Developer Dashboard。OAuth 沿用 PKCE，不使用 Client Secret。
2. 接著選「啟用歌詞」：在 Spotify 網頁登入並進入播放器，再按「完成」。也可選「稍後設定」；略過時播放器顯示「歌詞尚未啟用」與啟用入口，不先嘗試取詞。播放和歌詞目前仍需要分別登入。
3. 確認狀態後點「開始使用」進入播放器。取消授權／歌詞登入會留在原步驟；切換 App 或關閉後重開會恢復已保存的進度。被系統結束的 OAuth 視窗需重新發起，已完成的步驟不必重做。只有點「開始使用」才標記引導完成。
4. 手機安裝並登入 Spotify 後，回到主畫面按播放。App 先用已保存的 Web API 授權嘗試播放；只有沒有可用裝置時才透過官方 Spotify iOS SDK 喚起 Spotify，並透過 `spotifytrans://callback` 返回。播放控制需要 Premium 與 `user-modify-playback-state` 權限。App Remote 授權未完成不會清除已有 Web API 登入。
5. 日後由「設定 → Spotify 帳號」管理重新授權、歌詞登入及登出。歌詞缺少時間標記時顯示一般閱讀模式；取詞失敗可重試或更新歌詞登入。

### 開發者建置設定

- `Configuration/Spotify.xcconfig` 的 `SPOTIFY_CLIENT_ID` 是 App 的公開識別碼，透過 `Info.plist` 的 `SpotifyClientID` 提供給 App。Debug／Release 共用此設定，可用 Xcode 建置參數覆寫；不要加入 Client Secret。
- Spotify Developer Dashboard 需設定 bundle ID `order.SpotifyTrans`、Redirect URI `spotifytrans://callback`，並勾選 iOS SDK。內建 Client ID 不會解除 Spotify 開發模式的使用者名單、配額或公開發佈資格限制。
- 僅 Debug 的「開發者設定」可覆寫 Client ID；留白使用 App 設定。Release 不顯示輸入框、Developer Dashboard 連結，也不讀取 Debug 覆寫。
- 既有 Session 的更新與重新授權沿用原 Client ID；不直接把舊 Token 換綁到新 ID。若要改用內建 ID，先登出再連接即可。
- 引導步驟、歌詞稍後選擇與完成版本以一份 `lyriva.onboarding.progress` 保存於 UserDefaults，Token／Cookie 仍只放 Keychain。暫時無法讀取播放 Keychain 時等待重試，不誤判為首次安裝；已完成的引導不因讀取失敗而重設。
- `OnboardingTests` 驗證進度恢復、舊登入遷移、憑證不可讀／失效、取消及錯誤回呼、原 Client ID 保留。`OnboardingUITests` 使用獨立 defaults 和本機模擬授權／歌詞登入，驗證取消、背景返回、重開、略過及完成；不使用真實帳號。真實 Spotify 系統登入和網頁登入仍須實機驗證。

Spotify 官方 Web API 不提供歌詞。本機歌詞請求依據 spotify-lyrics-api 使用的非官方 Web Player 協定實作，不能直接讀取 Spotify App 的沙盒或 Cookie。若 Spotify 阻擋 WebView 登入、變更端點或協定，可能無法取得歌詞；目前尚未用使用者的真實帳號驗證。

## 本機中文翻譯

- iOS 26.4 以上優先採用 Apple Translation 的 [`highFidelity`](https://developer.apple.com/documentation/translation/translationsession/strategy/highfidelity) 策略，讓支援且已啟用 Apple Intelligence 的裝置使用較流暢的翻譯模型；不支援時由系統回退至一般模型，較舊 iOS 保留原本流程。語言清單、可用狀態、手動下載及實際翻譯使用同一策略，避免已具備 Intelligence 模型卻被一般模型檢查擋住。仍在裝置端處理，不新增雲端 API 或費用。這不是整首歌的語境改寫，跨行語意、隱喻及混合片段的品質仍需實機試聽驗證。

- 在「設定 → 翻譯語言 → 翻譯範圍」可選擇「全部語言」（預設）或只翻指定的單一來源語言，選擇會保存在本機。語言清單使用獨立視窗，可捲動或搜尋語言名稱、代碼；開啟期間固定項目，避免背景模型狀態更新影響捲動。只翻日文時，英文等其他片段保留原文，不檢查或要求下載其模型；混合語言行會組合指定語言的譯文與其他語言的原文。切換範圍會重新處理目前歌曲。
- 在歌詞工具列開啟「中文」，可同時顯示原文、羅馬字與繁體中文；三項可各自開關，至少保留一項。選擇會保存在本機。翻譯尚未完成或無譯文時，保留原文作為後備顯示。
- 使用 Apple Translation 裝置端翻譯，不設定雲端 API Key、不將歌詞傳送至自架後端。播放頁先檢查模型，尚未安裝只提示「前往設定」，不主動要求下載。設定的「翻譯語言」頁動態列出系統支援的來源語言，逐一檢查至繁體中文的支援狀態，提供搜尋、手動下載、取消要求與重試；從歌詞提示進入時優先列出缺少的語言。中文直接轉繁體字，不列為模型下載項目。模型下載後可離線處理已取得的歌詞，取得 Spotify 歌詞仍需要網路。
- 模型由 Apple 系統管理。刪除需前往 iPhone「設定 → App → 翻譯 → 已下載的語言」（需安裝 Apple 翻譯），App 內提供路徑說明。取消會結束 App 的下載要求；系統已開始的共用模型下載不保證立即停止。iOS 26 使用禁止請求下載的 installedSource session；iOS 18 在建立工作及執行前檢查模型是否安裝。
- 按歌詞行 ID 對應譯文，共用原本的時間標記與自動捲動。日文、英文等來源語言各自分批並依序使用 Translation Session，遵守 [Apple 單一來源語言批次要求](https://developer.apple.com/documentation/translation/translationsession/translate(batch:))。同一句日、韓、英混用時依文字片段分組，已完成的譯文依原順序組回該行；缺少模型、辨識不明或翻譯失敗的片段保留原文，不阻擋同一句其他片段顯示。整行都未完成時沿用原文後備顯示。重複片段共用結果，失敗重試只請求尚未完成的部分。
- 英文與西班牙文共用拉丁字母，另以短詞組的語言候選及信心差距找出西文片段，並保護明確的英文詞組邊界；即使沒有標點，也可拆開可辨識的英西片段。辨識為西文的短句不再受一般的 20 字母門檻限制。重複行共用拆分結果，原有標點、空白與行 ID 保留；「只翻英文／西文」也套用到拆分片段。測試包含 Pitbull〈I Know You Want Me〉的最短數數片段，以及合成的英西交替句；並非完整歌曲或實機翻譯品質驗證。共同單字、俚語與非常短的片段仍可能有歧義，其他拉丁語言的句內混用尚未專門處理。
- 播放進度更新不重新翻譯。譯文僅保留目前歌曲於記憶體，換歌或歌詞內容改變時捨棄舊結果；關閉中文後不再接受未完成工作的結果。
- 日文假名與韓文片段直接使用對應來源語言；語言選單可協助判斷漢字片段，不會把英文強制套用日文翻譯。自動辨識會參考整首歌的假名及韓文線索；在日文／韓文歌曲或手動選擇日文／韓文時，短英文字母片段、反覆吟唱詞，以及缺乏明確辨識結果的較長英文字母片段按英文處理；有足夠信心的其他語言長句保留其語言。全形與特殊字型只在辨識時正規化，特殊撇號不再被拆成未知語言，單獨的延音／修飾符號保留原文；送交翻譯的文字保持不變。其他偵測需足夠長度與可信度，避免短句誤判後要求下載不相關模型。中文片段直接轉為繁體字。混合語言拆分後的語序、隱喻與跨行語意品質仍需實機驗證，不承諾逐句翻譯等同人工譯詞。
- 翻譯錯誤可重試，不阻擋播放或原文顯示。小工具目前仍顯示原文與羅馬字。
- Apple Translation 的模型執行需實機，模擬器顯示提示。已驗證模擬器與實機編譯，並以注入翻譯結果測試逐行對應、重複句、換歌、取消、錯誤重試與目前歌曲快取；尚未實機驗證模型下載及翻譯品質。
- 模型查詢回報尚未就緒時，先延遲 350 毫秒確認一次；若仍需下載，播放頁在前景閒置時以 1、2、4、8 秒間隔自動重查。模型恢復就緒會接續未完成的語言並保留已有譯文，不必進出設定頁。離開播放頁、切到背景或關閉中文會停止重查；不永久快取「已下載」，避免模型刪除後仍誤用舊狀態。

## 智慧讀音檢查

- 日文歌詞會以詞組檢查多音字、殘留 `~tsu`／助詞 `wo` 與可疑拼音。有疑義的行保留原文並顯示「讀音可能有歧義」。點提示可從完整詞組候選（例如「二人 → futari」）中選擇，不需要輸入日文或羅馬字。
- 可選擇保留原文，或恢復系統讀音。選擇儲存在此裝置，僅對應這首歌的特定位置；一般播放與練唱模式的羅馬字同步更新。
- 「永遠」可在讀音檢查選 `eien`／`towa`，依歌曲唱法保存；「もう一度」自動使用完整詞組 `mou ichido`，不再依孤立的「一／度」拼接。特殊語境的「一度」另提供 `hitotabi` 候選。
- 目前使用本機規則及小型候選詞典，無法判定歌手的特殊唱法；無可靠候選時只提示歧義。英文、中文不套用日文候選。設計與詞典參考見 [讀音檢查說明](design/reading-review.md)。

## 轉寫與資料保存

- 使用 Foundation / NaturalLanguage 的裝置內建能力，不呼叫 LLM，不上傳歌詞作翻譯。
- 混合歌詞依文字片段轉寫，英文大小寫、標點與既有空白保留；日文使用日文斷詞讀音，其他文字使用系統拉丁字母轉寫。自動模式會參考整首歌的假名線索，改善「世界」「未来」「夢」等獨立漢字詞的日文判斷，同時保留仍辨識為中文的片段。只有漢字或中日混合的歌詞仍可能有歧義，可從語言選單選「日文」；未知字保留原文，歌曲特殊讀音不保證與歌手唱法相同。
- 修正系統將促音拆成 `~tsu` 的輸出：例如 `しまっ` + `た` 組回 `shimatta`，不把小「っ」當作獨立的 `tsu`。句尾小「っ」用 `’` 表示截斷；正常「つ」仍保留 `tsu`，助詞「を」顯示為 `o`。規則只作用於日文片段，手機與小工具共用，原文及送交翻譯的文字維持來源內容。
- 分詞後獨立的「は」按助詞讀作 `wa`，例如「君は → kimi wa」；「こんにちは／こんばんは」也使用 `wa`。「はな」「はじめ」、漢字「葉」及片假名「ハ」保留原有的 `ha` 讀音。
- 轉寫在背景工作執行，避免阻塞介面。
- 不快取歷史歌曲。只保留目前畫面使用的歌詞；換歌、切換語言或按「重新取得」時重新抓詞與轉寫。同一首歌的重複同步不重載；手動重新取得期間保留目前歌詞，成功後才替換。
- 依目前需求，不建立 Excel、CSV 或資料庫。取得歌詞需要網路；小工具只保存目前歌曲的顯示資料與有限的預排歌詞，換歌覆蓋。
- 前景每 5 秒校正 Spotify 歌曲與進度，暫停／跳播狀態最多約有 5 秒偵測延遲；網路延遲會增加時間。播放進度在兩次回應之間本機估算。App 進入背景停止輪詢。定期同步不顯示讀取動畫；暫時失敗時保留目前歌曲與歌詞，凍結進度直到同步恢復。

## 主畫面歌詞小工具

- 用 Xcode 安裝此版並開啟 App 同步一首歌後，長按 iPhone 主畫面 → 加入小工具 → 搜尋「Lyriva」。提供小、中、大三種尺寸；大尺寸另外顯示下一句。點擊小工具可返回 App。
- 歌詞超出寬度時自動換行，小、中尺寸目前原文最多兩行，大尺寸最多三行；羅馬字依剩餘空間換行，超過可用行數才顯示省略號，底部保留播放控制。
- 底部提供上一首、播放／暫停、下一首，可直接控制 Spotify 的活動裝置，操作後重新讀取播放狀態與歌詞；需要 Spotify Premium 與播放控制授權。沒有活動裝置時提示先在 Spotify 開始播放。未取得有效登入的小工具按鈕會停用。
- 中央播放／暫停使用 WidgetKit 的 `Toggle` 與自訂圖示樣式，點下時由系統立即切換圖示，不等待網路或歌詞下載；保留置中、無底框的外觀。每次切換在取得控制鎖後依共享播放狀態決定指令，快速按兩次會依序暫停、播放，不沿用舊時間軸的暫停指令。失敗時依實際播放回應校正圖示；無回應時回復操作前的狀態並顯示錯誤。
- 小工具收到操作先停止舊歌詞時間軸；跨程序控制鎖涵蓋播放指令與短暫的狀態確認，歌詞／封面下載在釋放鎖後執行。即使指令逾時或回傳錯誤，仍查詢 Spotify 的實際狀態，已確認切歌就先更新歌名，再補歌詞，不重送可能已執行的切歌指令。每次操作的識別會保留到歌曲載入完成，防止前一次慢回應覆蓋後一次切歌或暫停。403 依回應原因區分播放限制、Premium 與授權不足。系統實際重繪時機仍由 WidgetKit 決定；注入回應測試涵蓋連續切歌、錯誤後已換歌，以及歌詞延遲回寫，仍需實機驗證。
- 有時間標記且 Spotify 正在播放時，將目前歌曲的未來歌詞時間預先交給 WidgetKit，依最後取得的播放位置推算換句。沒有時間標記、暫停或同步失敗時，保留最近取得的那一句。
- iOS 可能延後或合併時間軸更新，Apple 建議時間軸項目至少相隔約 5 分鐘，因此每幾秒換詞屬於實驗性嘗試，不能保證即時同步。App 進入背景後停止輪詢，但 WidgetKit 允許執行小工具時，小工具會自行向 Spotify 查詢目前播放歌曲、讀取歌詞並在裝置上轉寫。自然接續下一首不再只重讀上一首的 JSON；仍不能保證在切歌瞬間或每句時間點執行。回 App 可立即校正。
- 預計歌曲結束後 2 秒請求下一次更新；每次請求至少相隔 60 秒，長歌、暫停或失敗時約 5 分鐘後請求重試。這些是希望執行的日期，並非背景定時器，iOS 可能延後很久。過期後顯示等待更新；無歌詞的新歌仍更新歌名，204／非歌曲清除舊歌，429 遵守 Retry-After。單次工作設 22 秒取消期限。手機主畫面的實際更新頻率尚待驗證。
- App 和 `SpotifyTransWidgets` 透過 App Group `group.order.SpotifyTrans` 共用一份 `current-song.json`，只含目前歌曲資訊、縮小封面，以及最多 256 句目前／未來歌詞與時間標記。換歌覆蓋，不建立歷史歌詞庫，不在 JSON 中存放 Token 或 Cookie、不需要後端；中斷 Spotify 連線時清除。App 與小工具透過共享 Keychain 取得登入，檔案鎖協調更新，較舊的歌曲回應與封面不覆蓋較新的資料。
- 暫停時點小工具進入 App，會取消舊的 Spotify 啟動確認與延遲授權回呼，再讀取播放狀態，不自動播放。冷啟動可先還原同一帳號最近 15 分鐘內的暫停歌曲及進度；空播放回應保留已知暫停歌曲並顯示等待同步，實際讀到歌曲（包含暫停）後清除舊啟動錯誤。這不會清除或重建登入憑證。
- 兩個 target 已設定相同的 App Groups entitlement。實機安裝時，簽署用的 Apple Developer 團隊與 provisioning profiles 必須支援此 App Group；若改 bundle ID，也需一併調整兩份 entitlement 與共享模型中的群組名稱。

## 登入資料

- 歌詞登入由使用者在 App 的 WebView 完成，只擷取該 WebView 中 Spotify 網域的 `sp_dc` Cookie，按下「完成」後保存。WebView 使用持久化的 WebKit 資料存放區，在 App 沙盒保留網站登入狀態，重新開啟登入頁可沿用。
- 供 App 與小工具使用的 Cookie 與官方 OAuth 憑證保存在共享 Keychain，使用 `AfterFirstUnlockThisDeviceOnly`（重新開機後需先解鎖一次）；不寫入偏好設定、歌詞資料、日誌或 Git。WebKit 另外管理自己的網站資料。帳號頁的「管理帳號 → 登出 Spotify」一併清除播放憑證、歌詞憑證及 App 內的 WebKit 網站資料，不登出 Spotify 官方 App。
- Cookie 僅送至 `open.spotify.com/api/token`；短期 Web Token 僅送至 Spotify 歌詞端點。拒絕 HTTP 重新導向，保留系統 TLS 憑證驗證。
- 歌詞協定需從公開 GitHub 來源下載協定常數，該請求不附 Cookie／Token。這代表仍依賴外部網站，但不需要自己維護後端。
- 需要喚起 Spotify 時使用官方 `SpotifyiOS` Swift Package（固定 5.0.1），不需要後端。SDK 返回後，不論其額外授權是否成功，都用原有 Web API 授權查詢實際播放狀態；必要時補送一次播放指令，不反覆喚起 Spotify。不把「已開啟 Spotify」當作已播放成功，也不將 App Remote 回傳的 Token 用於 Web API。
- 從 Spotify 返回後，即使沒有收到 SDK 回呼，也會開放前景播放查詢，最多等待 15 秒確認；暫時空白或同步失敗不立刻判定啟動失敗。逾時後恢復一般前景重試，後續取得實際播放中的歌曲會清除啟動提示；不需要反覆按播放喚起 Spotify。
- 官方 OAuth Access／Refresh Token 與 Client ID 存在此裝置的共享 Keychain，App 重啟可恢復登入，小工具可自行更新過期 Token。跨程序的檔案鎖避免同時旋轉 Refresh Token；登出後不接受遲到的更新回應。Client ID 本身是公開識別碼，也可保存在本機偏好設定。
- 沿用已存在的共享登入與舊歌詞 Cookie 遷移，不因改名或此版登入頁變更要求重新登入。暫時無法讀取 Keychain 或網路錯誤不會清除憑證。兩個 target 使用既有 App Group 作為 Keychain access group，實機須有有效簽署與 App Groups 設定。
- Access Token 到期會自動使用 Refresh Token 更新；播放 API 的 401 不會直接登出，歌詞短期 Token 的 401 也會使用已保存的 Cookie 更新並重試一次。只有 Refresh Token 回報 `invalid_grant` 或歌詞登入確認失效時才提示更新授權，避免反覆要求登入。
- 無法保證永久免登入：[Spotify 2026 年 6 月公告](https://developer.spotify.com/blog/2026-06-18-refresh-token-expiration)將 Developer Dashboard 應用的 Refresh Token 壽命訂為授權後六個月，2026 年 7 月 20 日生效。使用者撤銷授權或網站 Cookie 失效也可能需要重新登入。

## 驗證

測試使用 iPhone 16 Pro／iOS 18.4 模擬器，包含小工具資料覆蓋／過期／三種尺寸渲染、日文漢字上下文轉寫、首次播放啟動回呼、取消／重試、日英文混合歌詞轉寫、同曲更新保留歌詞、同步失敗與恢復、重播重新取詞，以及封面資料解析。

- 單元測試使用模擬 HTTP 回應，涵蓋非官方歌詞請求、憑證傳送範圍、一次性代碼、HTTP 錯誤、轉寫、重播重新取詞與換歌競態。
- 新增測試涵蓋自然換歌後重新抓取歌詞、缺詞換歌、暫停／無播放、歌曲結束後持續請求、舊封面防覆寫、並行 Token 更新、登出競態、401 更新與 429 重試。
- 真實帳號登入、App／小工具共享 Keychain、背景自然接續歌曲的實際更新延遲、首次喚起 Spotify／返回 App、Premium 播放控制與歌詞可用性仍待實機驗證。

自訂 callback scheme 依 Spotify iOS 文件設定；若 Dashboard 對你的 App 要求 HTTPS，需改用自有網域 Universal Link 並設定 Associated Domains。
