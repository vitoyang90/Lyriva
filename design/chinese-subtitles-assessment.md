# Lyriva：繁體中文翻譯字幕評估

評估日期：2026-09-12。已依使用者指示實作 Apple 裝置端翻譯，支援原文、羅馬字與中文同時顯示。下方為原始產品評估；授權與實機翻譯品質仍需另行驗證。

## 建議

適合納入下一階段功能，讓使用者從「跟著唱」延伸到「理解歌詞」。正式接入前，先確認歌詞來源允許顯示及翻譯，再驗證繁體中文品質與閱讀體驗。目前不建議把既有非官方 Spotify 歌詞直接交給 AI 翻譯後推出。

## 第一版範圍

- 在歌詞工具列加入「中文」開關，預設關閉，記住使用者選擇。
- 依使用者確認，開啟中文後可同時顯示原文、羅馬字、繁體中文；三項各自提供開關，至少保留一項。
- 沿用原文的行 ID 與時間標記同步中文；翻譯只負責文字，不產生播放時間。無時間標記的歌曲僅提供對照閱讀。
- 先顯示原文，翻譯在背景準備；失敗不阻擋播放與歌詞。換歌時取消舊工作，避免舊譯文覆蓋新歌。
- 第一版先支援 App 內歌詞，小工具待閱讀密度與同步體驗驗證後再加入。

## 翻譯品質

目標是解釋語意，不承諾可直接演唱的押韻譯詞。實測應包含日文省略主詞、韓文敬語、英日混合、跨行句子與重複副歌。需要區分繁體字轉換與符合繁體中文習慣的翻譯，不能只把簡體結果轉字就視為完成。

優先使用來源已提供且授權允許展示的中文譯文。若需機器翻譯，需確認來源允許該用途，並檢查漏行、合併行、重複行和人名一致性。整首或分段翻譯可保留上下文，但仍須驗證結果與原行的對應。

## 技術與成本

現有 `LyricsDocument.Line` 已有 ID 與時間標記，`PhoneLyricsStore` 也有換歌時捨棄過期結果的機制，適合新增依行 ID 對應的譯文。無須重新做音訊辨識。

若內容授權允許機器翻譯，可先評估 Apple Translation：支援裝置端模型及批次文字翻譯，不需自行呼叫雲端翻譯服務。需要處理首次語言模型下載、語言組合可用性，並在實機驗證繁體中文結果；目前未測試歌詞品質。參考 [Apple Translation API](https://developer.apple.com/videos/play/wwdc2024/10117/)。

雲端方案需計算翻譯用量、後端與失敗重試成本；授權來源也可能有獨立費用。目前沒有實際供應商報價或用量資料，不宜先承諾每月成本。無論使用哪種服務，都應在使用者開啟功能後才翻譯，避免每次播放進度更新重複處理。

## 目前的主要限制

程式使用 Spotify 未公開的網頁歌詞介面。Spotify Developer Policy 第 III.14 項限制將 Spotify 內容輸入機器學習或 AI 模型，其表述不只針對訓練。我的判斷是：目前不能把「裝置端處理」或「不拿來訓練」視為已取得翻譯許可。應先取得適用許可，或改採允許此用途的授權歌詞／譯文來源。參考 [Spotify Developer Policy](https://developer.spotify.com/policy)。

Musixmatch 提供授權歌詞 API，可作為來源洽詢方向；仍需另外確認繁體中文譯文覆蓋率、翻譯權限、儲存期限與費用，不能假設歌詞 API 自動包含這些權利。參考 [Musixmatch 官方 API 工作區](https://www.postman.com/musixmatch-dev)。
